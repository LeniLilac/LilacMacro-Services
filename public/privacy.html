Privacy Policy

This Privacy Policy explains how the independent LilacMacro community project ("LilacMacro," "we," "us," or "our") handles information through the LilacMacro Windows app, website, hosted services, and support tools (the "Services"). The app performs automation locally. This Policy describes what remains on your device, what optional features send, why we use that information, and the choices available to you.

Effective date: August 15, 2026. Last updated: August 21, 2026.

Summary

  • Core automation, Plans, settings, and visual profiles operate locally.
  • Online features, product telemetry, and Deep Debug error uploads are separate choices. All three are initially shown on, but none begins until you save the first-run screen.
  • We do not sell personal information, show targeted advertising, or use public-site analytics or tracking cookies.
  • Diagnostic archives are private, limited to 3 GiB each, and available to us for no more than 72 hours. They may be deleted sooner when the shared 1,000 GB allocation is full.

Scope and contact

This Policy applies to information handled by the Services. It does not govern Roblox, Anime Expeditions, Discord, GitHub, Cloudflare, or other third-party services, which have their own policies. LilacMacro is operated through the LeniLilac GitHub organization. For privacy questions or requests, email lilithlilac000@gmail.com.

Your privacy choices

Before the first macro session, the app presents three separate choices. All are initially shown on. No covered request or upload begins until you select Save & Continue. You can change each choice later in Settings. Turning a choice off stops new activity for that feature; a bounded network request already in flight may finish.

  • Online services and updates. Requests signed service status, public game codes, maintenance notices, safety disables, official update metadata, and configuration sharing that you explicitly request.
  • Usage data. Sends fixed-format events about feature use, reliability, expedition rewards, OCR performance by normalized CPU/GPU model, and display/UI-scale calibration.
  • Deep Debug error uploads. After a classified macro error, sends the completed Deep Debug archive. Uploading pauses while Deep Debug logging is off or low disk space temporarily disables it.

Information we process

Website and service requests

Cloudflare and our hosting provider process network information, including source IP addresses, to deliver and protect requests. The application temporarily uses a normalized source address for rate limits and keyed pseudonyms, but does not store the raw address in its database or application logs. Application logs contain bounded operational details such as request method, fixed route, response status, and timing. They omit request headers, bearer codes, and source addresses.

Online services and configuration sharing

Online services may retrieve signed operational status, public game codes, safety notices, and official GitHub release metadata. If you export a configuration, the app sends only the Plan and/or map placement documents you selected as one compressed bundle. It excludes private-server links, Discord settings, privacy choices, run history, diagnostics, and unrelated app settings. We store the opaque bundle, its checksum, timestamps, and a monthly rotating network pseudonym used only for abuse limits. We store only a hash of the random 20-character share code. Anyone with the code can retrieve the bundle before it expires, so keep it private.

Usage data

Analytics uses a closed schema containing app version; feature and outcome identifiers; expedition material and quantity observations; bounded error-state counters without free-form exception text; OCR duration, CPU or GPU execution category, and a normalized public CPU/GPU model name; primary-display pixel dimensions; bounded UI Scale input and rendered-scale values; Windows version; and logical processor count. Model names are accepted only for known CPU/GPU vendors, stripped of trademark punctuation and unsupported characters, and limited to 96 characters. It does not contain screenshots, OCR text, file paths, Roblox credentials, private-server links, Discord webhook URLs, hardware serial numbers or device IDs, or raw IP addresses.

The app creates a random installation UUID. The service immediately transforms that UUID and the normalized source network into separate monthly rotating HMAC pseudonyms and stores neither source value. Analytics and diagnostics use separate HMAC domains, so their stored pseudonyms are not directly joinable in the database. We use aggregates to estimate active installations, find error-prone states, understand feature use, compare OCR performance by hardware model, calibrate UI Scale across display resolutions, and support manually reviewed reward research. Aggregates never automatically change macro behavior, reward distributions, or remote safety policy.

Settings displays the installation UUID so you can copy it when support asks for it. If you choose to provide that UUID, an authorized administrator can use it to locate diagnostic archives associated with the same installation during the 72-hour archive-retention window. The search value is sent in a non-cached request, immediately converted to the current and previous monthly diagnostic pseudonyms, and is not stored in archive metadata or returned by the search.

Deep Debug error uploads

LilacMacro has no manual diagnostic-upload feature and does not create a smaller fallback report. When both Deep Debug logging and automatic error uploads are enabled, a classified error can send the completed Deep Debug archive. An archive can contain the run's structured timeline, macro actions, sanitized logs and configuration context, and selected Roblox frames from important transitions and approximately 10 seconds before and after classified errors. Frames can contain information visible inside Roblox. Archives exclude credentials, webhook URLs, private-server links, and raw file paths through client-side redaction, but no redaction system is perfect.

Each archive is limited to 3 GiB. The client binds the exact archive size and SHA-256 digest to the upload. The archive remains private and is not fully read by the service unless an administrator requests a download. A requested archive is verified against its bound size and digest before download; invalid archives are deleted. Sent and failed archives remain in the local shared Deep Debug folder until the app's configured storage limit requires cleanup.

Administrator authentication and records

The private administrator console is protected by Cloudflare Access and Discord OAuth. Those services process the authorized email address and Discord account information needed to authenticate the administrator. LilacMacro requests Discord's identity scope and stores the authorized Discord user ID, short-lived OAuth state, session records, CSRF protection data, and immutable administrative audit entries. The public Services do not offer user accounts.

We disclose only the information needed to operate the Services to Cloudflare for content delivery, abuse protection, and administrator access; Hetzner for application and database hosting; Backblaze B2 for private diagnostic storage; GitHub for source code and official releases; and Discord for administrator authentication and user-configured webhooks. These providers process information under their own terms and policies. We may also disclose information when required by law or reasonably necessary to protect users, the project, or the public. We do not sell personal information or disclose it for targeted advertising.

Retention

  • Configuration shares: retrieval expires no later than 30 days after creation, followed by bounded deletion retries.
  • Usage data: rows and their capacity records become eligible for scheduled deletion after 90 days.
  • Deep Debug archives: access expires no later than 72 hours after upload. Archives can be deleted sooner to keep total retained allocation within 1,000 GB. When space is needed, the service selects the oldest archive from the installation with the most retained archives, recalculates counts, and repeats until the new archive fits. Count ties use the oldest archive globally.
  • Administrator authentication: OAuth attempts expire after 5 minutes and application sessions after 8 hours. Security and audit records are kept as needed to protect and account for administrative actions.

Expiration ends normal access and queues deletion. A provider outage or failed deletion may delay physical removal; the service retries and restores failed diagnostic deletions to capacity accounting. Local settings, Plans, visual profiles, and Deep Debug archives remain on your device until you delete them or a described local retention or successful-upload rule removes them. Uninstalling the app does not silently erase user-created data.

Cookies and similar technologies

The public website does not use advertising, analytics, or tracking cookies. The private administrator console uses secure, necessary cookies for OAuth browser binding and the administrator session. Cloudflare may use necessary security and access cookies under its own policy.

Security

We use HTTPS, access controls, purpose-separated credentials and pseudonyms, private object storage, bounded schemas, checksums, rate limits, and audit logging. No security measure can guarantee absolute protection, and you should avoid placing secrets or unrelated personal information on screen while Deep Debug logging is active.
