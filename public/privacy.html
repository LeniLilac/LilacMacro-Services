PRIVACY / NOTICE 01

Your choices control what leaves the app.

LilacMacro performs its automation locally. Before the first macro session, the app shows three separate choices. Online features and product telemetry are initially shown on; automatic error reports are initially off. Nothing covered by those choices is sent until you save the screen, and every choice can be changed later in Settings.

Online features

When enabled, LilacMacro requests signed service status, public game codes, remote safety disables for known bugs or maintenance, and official GitHub release metadata. It can also use service-backed configuration sharing when that feature is available. Turning this off prevents new LilacMacro service and update-check requests. One bounded request already in flight can finish and update its local public cache. Local automation remains available, but it will not receive current maintenance or safety status.

Product telemetry

When enabled, the app sends a fixed, bounded event schema: app version; feature and outcome identifiers; expedition material and quantity observations; error-state counters without free-form exception text; OCR duration and CPU/GPU execution category; Windows version; logical processor count; and process capability. Telemetry never includes screenshots, OCR text, file paths, Roblox credentials, private-server links, Discord webhook URLs, raw hardware identifiers, or raw IP addresses.

A random installation UUID is created locally. The service immediately converts it and the normalized source network to separate rotating HMAC pseudonyms and stores no raw UUID or IP address. The network pseudonym is used only for a daily abuse quota. Pseudonyms rotate monthly using domains separate from diagnostic reports. Telemetry is used to estimate active installations, understand feature use and error-prone states, tune OCR performance, and inform manually reviewed expedition reward research. It is retained for no more than 90 days. Aggregates never automatically change macro behavior, reward distributions, or remote control policy.

Automatic error reports

Automatic reports are a separate opt-in and are off initially. With Deep Debug off, an error can create a temporary light report containing a sanitized event timeline, non-secret display and plan counts, coarse device information, model/profile identifiers, macro actions, and at most 32 already-acquired important frames. The archive has an 80 MiB hard limit. OCR text, free-form exception text, paths, private-server links, Discord data, and credentials are excluded, but Roblox pixels can still contain personal game data.

With Deep Debug active, the completed Deep Debug archive is sent instead. Temporary light files are removed after the upload attempt. A successfully sent Deep Debug archive is removed; a failed Deep Debug upload remains local so you can inspect or retry it. When automatic reports are off, the app neither creates a light report nor automatically sends or deletes your Deep Debug archives.

Manual diagnostic uploads

Settings also offers a separate manual upload control. It remains off until enabled and always requires you to choose a specific ZIP. Routine archives expire after 72 hours. Archives over 3 GiB require a short-lived administrator grant and can be retained for at most seven days after explicit acceptance. Archives stay in private object storage and are never served as public content.

Service records and providers

The service keeps bounded request metadata, object keys, checksums, application versions, and rotating abuse-prevention pseudonyms. It does not store raw IP addresses. Hosting and delivery may involve Hetzner infrastructure, Cloudflare networking, PostgreSQL storage, Backblaze B2 private object storage, GitHub Releases, and Discord authentication for the administrator console. Those providers process limited service data under their own terms.

Local data and control

Settings, plans, visual profiles, local logs, and Deep Debug archives remain on the Windows device unless a feature described above sends them. Uninstalling does not silently erase user-created datasets or retained diagnostics. Use ordinary Windows file management to remove local data. To ask about server-held data, open a repository issue without including personal data and request a private contact channel.
